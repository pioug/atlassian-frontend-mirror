Use `IconMotion` to apply entry and exit animations to icons. Pass a pre-defined iconography motion
token to `enteringAnimation` and `exitingAnimation`.

It also supports motion that moves an icon in response to an interaction, such as someone clicking a
button. Each is its own component on `IconMotion`. Currently, there is only `IconMotion.Rotate`.

`IconMotion.Rotate` takes every `IconMotion` prop, plus `isActive`, which holds the rotated pose
when it is `true`, and eases the icon back when it is `false`. You decide when the motion plays and
pass the result to `isActive`.

The following sections describe the usage guidance and scenarios for applying motion to icons.

## Change an icon

Show that something changed.

### Fade out, fade in

When an icon becomes a different icon after a press or a change in state, the first fades out and
the second fades in. The most widely available effect: it works on any supported icon, because it
moves nothing inside the icon.

By default, the icon fades to clear over 250ms, is replaced, and the new icon fades to solid over
250ms. Where the surrounding transition is particularly fast, use the [fast](#fast-change) variant,
which runs over 50ms.

| Usage guidance |
| -------------- | -------------------------------------- |
| Icons          | Any [Atlassian icon](/components/icon) |
| Trigger        | Press or click, or a state change      |
| Use for        | Transitioning one icon to another      |
| Not for        | Hover                                  |

<Example packageName="@atlaskit/motion" Component={IconMotionSwap} title="Change an icon" />

#### Fast change

Use the `fast` tokens, `motion.iconography.exit.fade.fast` and `motion.iconography.enter.fade.fast`,
when the surrounding transition is particularly fast, such as the Side Nav. The whole icon fades
from clear to solid over 50ms, so the icon change keeps pace with the movement around it instead of
trailing behind.

| Usage guidance |
| -------------- | -------------------------------------------------------------------------- |
| Tokens         | `motion.iconography.exit.fade.fast`, `motion.iconography.enter.fade.fast`  |
| Use for        | An icon change inside a particularly fast transition, such as the Side Nav |
| Not for        | A general speed-up. Default to 250ms                                       |

## Bring an icon on or off

Show that something now applies, or no longer does.

### Fade in, fade out

The same fades can bring an icon on screen or take it away. Do it only when its presence is the
information: a status that has started or stopped applying. Nothing should vanish for a reason the
person cannot see.

By default, the icon fades in over 250ms when the thing it stands for starts to apply, and out over
250ms when it stops. Where the surrounding transition is particularly fast, use the
[fast](#fast-on-or-off) variant, which runs over 50ms.

| Usage guidance |
| -------------- | ------------------------------------------------------------------ |
| Icons          | Any [Atlassian icon](/components/icon)                             |
| Trigger        | A state change the person caused or will want to notice            |
| Use for        | A status that is now true, such as flagged                         |
| Not for        | Hover. An icon vanishing without a visible cause. Tidying a layout |

<Example
	packageName="@atlaskit/motion"
	Component={IconMotionEnterExit}
	title="Bring an icon on or off"
/>

#### Fast on or off

The `fast` tokens bring an icon on or off over 50ms. Use them under the same condition as for
changing an icon: the surrounding transition is particularly fast, such as the Side Nav. Pair
`motion.iconography.enter.fade.fast` with `motion.iconography.exit.fade.fast`. Don’t mix a fast
token with a default one.

	Component={IconMotionEnterExitFast}

## Send or move forward

The icon slides out of its box as a copy slides in behind it, so the action reads as something
leaving in a direction.

**Direction carries meaning.**

Cycle moves toward where the result or the next step will appear. In Rovo, the prompt box sits low
on the page, and what Rovo generates, or how the conversation continues, appears above it. Send
cycles upward, so the arrow guides the eye up from the input to the response.

Cycle can travel in any direction, but upward in the Rovo Send Button is the only recommendation so
far. A new direction needs a meaning of its own: where will the result appear?

### Cycle

The up-arrow slides out of the button’s box over 400ms while an identical copy slides in behind it.
`IconMotion` clips both to the icon's box. Use `overshoot` to widen the clip to match the space
around the icon, such as the padding of the button it sits in. Pass a space token, such as
`overshoot={token('space.075')}`. The icon travels that far past its box, so it just clears the
clip. `overshoot` only applies to the `cycle` motion tokens.

Inside a `Button` or `IconButton`, return `IconMotion` from the icon render function and use the
`motionOvershoot` that the button passes in `iconProps`. It already matches the button's `spacing`.

| Usage guidance  |
| --------------- | ----------------------------------------------------------------------------------------- |
| Icons           | The up-arrow in the Rovo Send Button, and nowhere else                                    |
| Trigger         | Press, on send                                                                            |
| Direction       | Up: toward where the response appears. Other directions are open                          |
| Exit then enter | Set `shouldExitThenEnter={false}`. We want the new icon to enter while the old is exiting |
| Use for         | The one send action in Rovo chat                                                          |
| Not for         | Any other up-arrow, or any other button                                                   |

In this example the icon itself is not changing, so the animation **will not** automatically play.

Use a `ref` and call `reanimate()` to play the enter and exit animations of the current icon again.

The icon is swapped for a fresh copy of itself, so it follows `shouldExitThenEnter`. By default, the
icon exits and then enters again. When `shouldExitThenEnter` is false, the new copy enters while the
old copy exits, and the two overlay each other.

## Accessibility

- Give every icon a `label`, or give the button a `label`, so that its purpose is announced.
- An icon that is exiting is hidden from assistive technology, so a screen reader doesn’t announce
  it alongside the icon that replaces it.
- When someone prefers reduced motion, the swap finishes straight away without an animation. The
  interaction motion still changes the icon’s position, but without a transition.

Read more about [reduced motion](/components/motion/accessibility).
