## Nested

Nesting popups inside other popups works out of the box. However, be mindful that nested popups
quickly become confusing, inaccessible, and difficult to navigate. If you’re nesting a lot of
content, it’s time to move your experience to a new page instead.

## Focus

### Set focus

You can focus a specific element when opening a dialog popup. When `role` is `"dialog"` or
`"alertdialog"`, the `content` render props provide a ref `setInitialFocusRef` to be set on the
desired element. Until `platform-dst-top-layer` is cleaned up, a role gated on that flag
(`fg('platform-dst-top-layer') ? 'dialog' : undefined`) also gets it. Other roles do not get it: a
menu or listbox has a fixed focus rule, and a popup with no role must not take focus. Give the
dialog a `label` or a `titleId`. Only set focus to an element at the start of the popup, otherwise
people who use assistive technology may miss the content.

The specified element needs to be available in the document as soon as the popup is opened,
otherwise it will not be focused upon. This means it will not work for content that renders into the
popup content after it has already opened, such as async or lazy loaded content. In those cases, you
will need to manually set focus on the content once it is rendered.

<Example
	Component={PopupFocusExample}
	packageName="@atlaskit/popup"
	featureFlagSwitchers={['motionPopup']}
/>

### Disable autofocus

If an element is focused, setting the `autofocus` prop to `false` will ensure it keeps focus when
the popup is opened.

With the `platform-dst-top-layer` feature flag on, `autoFocus` has no effect and focus follows
`role`. The `dialog`, `alertdialog`, `menu` and `listbox` roles move focus into the popup when it
opens. To keep focus where it is, do not use one of these roles. One exception: if a focused
combobox or text field controls the popup, focus stays on that field.

<Example
	Component={PopupDisableAutofocusExample}
	packageName="@atlaskit/popup"
	featureFlagSwitchers={['motionPopup']}
/>

## Role

Use the `role` prop to set a role for the popup content. We do not forbid passing any of the aria
roles, but we strongly recommend using only `menu` or `dialog`. When the `role="dialog"` property is
passed, one of the following properties must also be added: `label` or `titleId`.

<Example
	Component={PopupWithRoleExample}
	packageName="@atlaskit/popup"
	featureFlagSwitchers={['motionPopup']}
/>

Use `DropdownMenu` whenever possible: this example is not a blessed, production-ready menu pattern.
If a complex interaction requires a `Popup` with `role="menu"`, the consumer must implement the menu
behavior. Give each action the appropriate menu-item role, move focus to a menu item when the menu
opens, support Arrow Up, Arrow Down, Home, and End navigation, and return focus to the trigger when
an action or Escape closes the menu. Preserve each menu item's native Enter and Space activation
behavior. Validate the complete interaction with the assistive technologies and browser environments
that the product supports. For the complete role and interaction requirements, refer to the
[WAI-ARIA menu role](https://www.w3.org/TR/wai-aria-1.0/roles#menu) and the
[ARIA Authoring Practices menu and menubar pattern](https://www.w3.org/WAI/ARIA/apg/patterns/menubar/).

## Full width

Use `shouldFitContainer` to fit the popup width to its parent's width. When set to `true`, the
trigger and popup elements will be wrapped in a `div` with `position: relative`. The popup will be
rendered as a sibling to the trigger element, and will be full width.
