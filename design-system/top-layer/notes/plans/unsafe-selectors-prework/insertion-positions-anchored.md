# Insertion position of the top-layer host — anchored adopters

Ground truth #3 for the "make every unsafe style in AFM work with top layer" plan. **Question:**
when the `platform-dst-top-layer` feature gate is ON, where in the DOM does the top-layer host
element (the `<div popover>` rendered by `@atlaskit/top-layer`'s `Popover`, or the `<dialog>`
rendered by its `Dialog`) get inserted **relative to the component's trigger, as seen from the
consumer's tree**? The only thing that matters is whether the host is a _bare_ sibling of the
trigger with no intervening DOM element that the design-system component renders itself. A
DS-rendered wrapper between the consumer's element and the host makes the host unreachable by a
consumer's `& > *` selector, so it is classified `wrapped` rather than `after-trigger`. Every row
below is gated: with the gate OFF these components portal to `document.body` (or render inline via
Popper) and no host exists in the consumer's child list at all. All hosts are also only in the DOM
while open or exit-animating (ground truth #1), so every row is an **open-state-only** hazard.

## Consequences for §0.5 (risk matrix)

- `@atlaskit/popup`, `@atlaskit/dropdown-menu`, `@atlaskit/select` (PopupSelect),
  `@atlaskit/tooltip` and `@atlaskit/inline-dialog` are **anchored / trailing-insert** adopters:
  they take the left-hand column of the §0.5 matrix, so bare `:first-child` / `:nth-child(1)` on the
  consumer's container stays 🟢 for them.
- `@atlaskit/react-select` and `@atlaskit/datetime-picker` are **`wrapped`**, i.e. strictly _safer_
  than either matrix column — the host never enters a consumer's child list, so no consumer `& > …`
  rule can see it. Their residual risk is confined to selectors that reach _inside_ the component
  (`& X` descendant rules, `:has()`, `& > * button`) and to overrides of the DS component's own
  internal classes.
- `@atlaskit/inline-dialog` has a second, gate-independent hazard worth flagging separately during
  Phase 1b triage: the `display: contents` trigger wrapper changes the consumer's child count/order
  even in the **closed** state, which the "open-state only" framing of ground truth #1 does not
  cover.
